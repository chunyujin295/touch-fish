选哪套 · 内容与容器要匹配

真实感的天花板不在模板精细度，而在内容与容器是否匹配。同一段小说塞进 CSDN 会从头违和到尾，塞进知乎专栏却毫无破绽。下表是按内容类型给的默认选型。

内容类型首选皮肤理由
中文技术书（架构 / 语言 / 运维）掘金留白最大、行高最舒服，连读一小时不累；技术腔与内容天然一致
小说 / 历史 / 传记 / 随笔知乎专栏单栏窄版最像"在看一篇文章"，没有代码块的位置压力，技术腔最少
手册 / 规范 / 事故复盘Confluence公司内部有人长时间看 wiki 完全正常；信息面板、标签、页面树天生就有
英文技术书 / 论文Stack Overflow问题当标题、答案当正文，映射最自然；英文排版原生
随时会被叫走（碎片时间）微信公众号页面短、断点清晰，"在电脑上看篇文章"是最不需要解释的行为
需要极强掩护（老板常走动）GitHub Issue讨论串读一小时没人怀疑；缺点是英文语境，中文书要改写口吻

建议组合：日常主用掘金 / 知乎（舒适），Boss Key 切到Confluence 的"发布回滚 checklist"（最像正在干活）。其余皮肤按书籍类型轮换，避免长期只显示同一个站点反而不自然。

Topic packs · 行业语境

皮肤解决的是"版式像不像"，主题包解决"话题像不像"。导航栏写着「前端 / 后端 / 人工智能」、推荐位全是 K8s、广告是云服务器——正文却是《内科学》，那么版式对了、语境错了，比版式错更容易被识破。主题包把导航、版块结构、推荐池、广告池、评论语气、术语口径一整套换掉，并且给每个包配一张禁忌词黑名单。

Slot contract · 注入点

槽位类型说明
article-titlestring章节标题，经各皮肤的标题包装器处理（Issue 会加 [Question] 前缀）
bodyBlock[]正文容器。引擎逐块 append，Block 类型到 DOM 的映射由皮肤决定
toc{id,text}[]章节内小标题。CSDN 渲染成右侧目录，掘金渲染成左侧大纲，GitHub 无此槽位
commentsComment[]评论流。GitHub 皮肤里同时承担"分段器"职责
stat-read / like / collectnumber数字噪声，按 30–90s 随机 +1，窗口失焦即停
ad-top / ad-side / ad-feedAd广告位。素材从站点风格分池抽取，同 seed 可复现

Verisimilitude checklist · 真实感清单

✓站点 favicon 与 title 完全对齐（含"(3条消息)"这类小尾巴）
✓标题包装器：同一章在知乎是疑问句、在 SO 是 how-to、在 Confluence 是手册名
✓面包屑、专栏收录条、版权声明、页脚备案号 —— 缺一个就露
✓广告位分层：通栏 / 侧栏 / 文中信息流，且标注"广告"二字
✓推荐位标题与书籍无关（"K8s CrashLoopBackOff 排查"），制造真实的噪声
✓评论语气分层：捧场 / 提问 / 挑刺，且与正文弱相关
✓代码块带语言标识 + 复制按钮，行高与真实站点一致
✓阅读量随时间缓慢自增；visibilitychange 时暂停
✓滚动时目录高亮跟随（真实站点都有的行为）

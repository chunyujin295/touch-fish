# 主题包设计（Topic Packs）

> 版本 v0.2 · 配合 `docs/PRD.md` 阅读 · 原型见 `prototypes/topic-lab.html`

## 1. 为什么需要这一层

皮肤解决的是"容器像不像"，但它只还原了**版式**。真正被老板扫进眼里的，是**文字**：

- 导航栏写着「前端 / 后端 / 人工智能」
- 侧栏推荐「K8s CrashLoopBackOff 排查」
- 广告写「云服务器 2 核 4G 首年 89」
- 评论区在聊「这个 PR 我合了」

如果此时正文是《内科学》第 4 章，这四行字加起来就是一封举报信。**版式对了、语境错了，比版式错更容易被识破**——因为语境错误是"语义级"的，人脑对语义矛盾极其敏感。

于是引入第三层匹配：

```
        内容（书）              容器（皮肤）            语境（主题包）
   内科学 · 心血管章    →    丁香园论坛版式    →   心血管版 · 病例讨论
```

三者必须同属一个行业。换任何一个，另外两个都要跟着换。

## 2. 八个主题包

首发 8 个行业语境。每个包不是一个"标签"，而是一整套可替换的页面语料：站点原型、版块结构、术语口径、推荐池、广告池、评论语气、禁忌词。

| # | 主题包 | 站点原型 | 版式 | 版块结构 | 术语口径（示例） |
|---|---|---|---|---|---|
| 1 | **教育** | 教师研修社区 | 论坛 | 教研 / 备课 / 试题 / 班主任 / 家校 | 文本细读、学习任务群、大单元、分层作业、学情分析 |
| 2 | **密码学** | 看雪论坛 | 博客 | 密码学 / 逆向 / 协议安全 / 合规检测 | Z_A、ENTL、SM2/SM3、PKCS#11、C_GetMechanismList、协同签名 |
| 3 | **信息安全** | 先知社区 | 博客 | 漏洞分析 / 攻防 / 应急响应 / 代码审计 | 利用链、打点、权限维持、SSRF、ATT&CK、蓝队值守 |
| 4 | **计算机科学** | 掘金 | 博客 | 后端 / 架构 / 分布式 / 数据库 / 云原生 | 一致性、ReadIndex、水位、副本、QPS、P99 |
| 5 | **医疗** | 丁香园论坛 | 论坛 | 心血管 / 影像 / 药学 / 指南 / 病例 | 主诉、现病史、辅助检查、鉴别诊断、循证等级 |
| 6 | **生物** | 小木虫 | 学术 | 分子生物 / 细胞 / 测序 / 论文投稿 | 批次效应、差异表达、单细胞、FDR、审稿意见 |
| 7 | **数学** | 数学中国 | 学术 | 分析 / 代数 / 概率 / 计算数学 | 紧算子、谱、一致有界、反例、构造性证明 |
| 8 | **物理** | 物理所论坛 | 学术 | 凝聚态 / 量子信息 / 光学 / 低温 | 退相干、T2*、1/f 噪声、衬底损耗、稀释制冷 |

> 关于"信息"：我按**信息安全 / 网络攻防**理解，与"密码"（密码学与国密实现）拆成两个包。如果你指的是信息论/通信或企业信息化，主题包是纯数据，换一份 JSON 即可，不动代码。

## 3. 三种版式

8 个包对应 3 种页面骨架，这才是"行业感"的主要来源：

| 版式 | 用在哪 | 结构特征 | 可信点 |
|---|---|---|---|
| **blog**（博客） | 密码、信息安全、计算机 | 面包屑 + 作者行 + 目录 + 右侧推荐 + 底部评论 | 长文天然合理，代码块有位置 |
| **forum**（论坛） | 教育、医疗 | 帖子标题 + 楼主卡 + 楼层回复（#1 #2 引用）+ 快速回复框 | **楼层号、引用块、`本帖最后由…编辑` 是论坛独有指纹** |
| **academic**（学术） | 生物、数学、物理 | 摘要卡 + 关键词 + 参考文献 + 讨论区 + 期刊页脚 | 素净、衬线标题、ISSN/基金号，与人文学术站一致 |

论坛版式的价值被低估了：一个"32 楼回复、带引用、带编辑记录"的页面，天然解释了你为什么停在这一页这么久——你在**追一个讨论**，这是最不需要解释的行为。

## 4. 主题包数据模型

主题包是纯数据，不含任何逻辑。皮肤层只认结构，主题包只填内容。

```jsonc
{
  "id": "med",
  "name": "医疗",
  "site": "丁香园论坛",
  "host": "www.dxy.cn",
  "layout": "forum",              // blog | forum | academic
  "accent": "#0891b2",
  "nav": ["首页", "论坛", "病例", "指南", "用药", "考试"],
  "crumb": ["论坛", "心血管", "病例讨论"],
  "titleStyle": "病例式",          // 标题包装器的口径
  "author": { "name": "…", "role": "…", "meta": "…" },
  "tags": ["急性冠脉综合征", "心电图"],
  "body": [ /* Block[]：p | h2 | code | quote | list | table | note */ ],
  "sidebar": [ { "h": "本版热帖", "items": ["…"] } ],
  "ads": [ { "t": "…", "d": "…", "cta": "…" } ],
  "comments": [ { "u": "…", "role": "…", "t": "…", "x": "…" } ],
  "terms": ["主诉", "鉴别诊断", "循证等级"],
  "banned": ["commit", "部署", "接口", "QPS"]   // 禁忌词：出现即露馅
}
```

**`banned` 是这套设计里最关键的一个字段。** 它定义"这个语境里不该出现什么"。医疗帖里冒出 `commit`、教育帖里冒出 `QPS`，比广告位少一个更容易被抓。

## 5. 术语一致性检查

渲染前跑一遍轻量校验，不通过就重抽噪声：

```
for word in pack.banned:
    if word in page.text: reject_and_reroll()
```

三级可信度，按书的类型选：

| 级别 | 做法 | 适用 | 成本 |
|---|---|---|---|
| **L1 直出** | 书的原文 + 该行业的壳，不改一个字 | 书本身就在这个行业（读《国密算法原理》用密码包） | 0 |
| **L2 轻包装** | 加行业小标题、术语高亮、摘要卡 | 跨行业但可迁移（读《思考，快与慢》用教育包） | 规则引擎 |
| **L3 改写口吻** | 把章节改写成"帖子体"，加提问/回复 | 内容与行业差距大（读小说用医疗包） | 需本地 LLM |

绝大多数情况 L1 就够。**只有当书本身不属于任何行业时，才需要 L3**——这也是为什么"内容与容器匹配"仍是天花板。

## 6. 组合矩阵

皮肤 × 主题包不是随便配的，有些组合天生矛盾：

| 你在读 | 主题包 | 推荐皮肤 | 说明 |
|---|---|---|---|
| 国密 / 密码协议 | 密码学 | 看雪式博客 | 术语、代码、合规讨论全对齐 |
| 内科 / 药理 / 影像 | 医疗 | 丁香园式论坛 | 病例讨论是医疗内容最自然的容器 |
| 教材 / 教研 / 教育理论 | 教育 | 教师社区论坛 | 教研帖天然长篇、天然有争议 |
| 分布式 / 语言 / 算法 | 计算机 | 掘金 / CSDN | 原方案 |
| 分子生物 / 基因组 | 生物 | 小木虫式学术页 | 摘要卡 + 方法段 + 参考文献 |
| 数学教材 / 习题 | 数学 | 数学中国式学术页 | 定理块、证明、"这步没看懂" |
| 物理 / 量子 | 物理 | 物理所式学术页 | 实验条件表、公式、组会语气 |
| 小说 / 历史 / 随笔 | 任意（建议教育/医疗） | 知乎专栏 / 微信公众号 | 人文内容跨行业仍自然 |

**反例（务必避免）**：医疗书 + CSDN 壳、小说 + Stack Overflow 壳、数学书 + 掘金壳。这三种组合的违和感在 1 秒内就能被察觉。

## 7. 落地计划

| 阶段 | 内容 |
|---|---|
| M2-a | 8 个主题包 JSON 定稿（本文件 + `topic-lab.html` 里的数据即初稿） |
| M2-b | 噪声生成器改为 `pick(pool, seed = hash(bookId, chapter, packId, skinId))`，同参数必复现 |
| M2-c | `banned` 校验 + 重抽循环，最多 3 次 |
| M3 | 主题包跟随书籍类型自动推荐（按 EPUB 的 subject / 章节词频打分） |
| M4 | L3 改写：本地小模型把章节改写成帖子体（含"楼主补充"“2 楼质疑"） |

## 8. 风险

- **专业度**：医疗、数学、物理的噪声文本必须由懂行的人过一遍。外行写的"医学黑话"比不写更糟——真医生扫一眼就知道是编的。
- **免责**：医疗包必须带"仅供同行学术讨论，不作为诊疗依据"这类真实论坛也有的声明；教育包不要虚构具体学校与真实教师姓名。
- **机构**：不要用真实医院、真实学校、真实公司名去做负面/争议内容，一律用虚构图谱。
- **商标**：站点名与 logo 仍按 PRD § 8 处理（相似版式、自有标识）。

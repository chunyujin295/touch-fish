# TouchFish · 摸鱼阅读器 — 需求与方案设计

> 版本 v0.1（方案稿） · 最后更新 2026-11-02
> 本文档只讨论**产品形态、技术方案与工程约束**；原型见 `prototypes/`。

---

## 0. 一句话定位

把**本地电子书**（EPUB / MOBI / AZW3 / TXT / Markdown）渲染成**以假乱真的技术社区网页**，让长时间阅读在开放式工位上"看起来像是在研究技术"。

**它不是**：伪装成 Word/Excel 的阅读器（那类工具的问题是——文档页没有"可读的噪声"，一眼就能看出屏幕在长时间静止滚动）；它是**把书塞进一个本来就应该长这样的网页壳里**。

---

## 1. 为什么"网页壳"这条路是对的

摸鱼工具的核心矛盾是：**内容要能长时间读，界面要经得起 3 秒瞥视**。

| 载体 | 长时间可读 | 3 秒可信度 | 结论 |
|---|---|---|---|
| 伪装成 Word/PDF | 中 | 低（长时间滚文档很可疑，且没有滚动条噪声） | ✗ |
| 伪装成代码编辑器 | 低（代码没法读小说） | 高 | ✗ |
| 纯黑底终端 | 低 | 中 | ✗ |
| **技术社区网页** | **高** | **高** | **✓** |

技术社区网页天然具备三个"掩护色"：

1. **长文本是它的正常形态**——一篇 CSDN 长文读 20 分钟完全合理；
2. **满屏噪声是它的正常形态**——广告、推荐位、评论、右侧目录，越乱越真；
3. **滚动是它的正常形态**——鼠标滚轮慢慢往下走，恰好像"在读一篇长文"。

**成功判定（验收线）**：把成品截图给 3 位同事，在 1280×800、只看 3 秒、无鼠标交互的条件下，问"这个人在干什么"——至少 2 人回答"在看技术文章/查资料"。

## 2. 用户与场景

**主用户**：技术岗（研发/运维/安全），工位背对过道或侧后方有同事，日均想读 30–90 分钟非工作内容。有大量本地电子书（技术书、小说、历史、传记）。

**三个核心场景**

| 场景 | 时长 | 关键要求 |
|---|---|---|
| S1 长时段阅读 | 20–60 min | 排版舒适、能记忆进度、翻页不穿帮 |
| S2 碎片阅读 | 3–8 min | 秒开、秒恢复到上次位置 |
| S3 老板临近（<3 s） | 瞬时 | 一键切走、切走后不留痕、切回无感 |

> S3 是**最高优先级**。所有"真实感"投入，都不能以牺牲"3 秒内能切走"为代价。

## 3. 核心信息模型

```
Book ─┬─ Chapter ─┬─ Block ──── (paragraph | heading | quote | code | list | image | table)
      │           └─ Block ...
      └─ Meta (title, author, cover, toc, language)

Skin  ─┬─ Slot      (具名坑位：title / meta / body / toc / ad-1 / comments / footer ...)
       ├─ Renderer  (Block 类型 → 该皮肤下的 DOM)
       └─ Chrome    (header / sidebar / floating rail / footer，纯装饰)

Ad      = 广告素材池中的一条（标题 + 副文案 + 主色 + 尺寸位）
Comment = 评论种子（用户名词 + 头像色 + 语气模板 + 相对时间）
```

**关键抽象：`Block` 是唯一跨皮肤的中立单位。** 解析层只产出 Block 序列，皮肤层只消费 Block 序列。这样新增一套皮肤 = 写一个 HTML + 一份 CSS + 一个 12 行的 block 映射表，不需要碰解析器。

### 3.1 数据契约（原型已按此实现）

模板中用 `data-tf-slot` 标记注入点，引擎用 `querySelector('[data-tf-slot="x"]')` 定位填充：

| slot 名 | 类型 | 说明 |
|---|---|---|
| `doc-title` | string | `<title>` 内容，含站点后缀 |
| `favicon` | dataURI | 站点图标，必须对 |
| `breadcrumb` | string | 面包屑末级 |
| `article-title` | string | 正文 H1 |
| `author-name` / `author-avatar` / `author-level` | string | 作者卡 |
| `meta-publish` / `meta-update` | string | 发布时间（可漂移） |
| `stat-read` / `stat-like` / `stat-collect` / `stat-comment` | number | 数字噪声 |
| `tags` | string[] | 标签 chips |
| `body` | Block[] | **正文容器**，逐块 append |
| `toc` | {id,text}[] | 侧边目录 |
| `ad-top` / `ad-side` / `ad-feed` / `ad-bottom` | Ad | 广告位 |
| `comments` | Comment[] | 评论流 |
| `related` | {title,meta}[] | 相关推荐 |

**幂等要求**：同一章、同一皮肤、同一 seed → 渲染结果必须完全一致（可复现的"噪声"）。否则每次刷新广告/评论全变，反而露馅。

## 4. 功能需求

### FR-1 书籍导入与解析

- 支持 **EPUB（主力）、TXT / Markdown（零依赖）、MOBI / AZW3（需转换）、PDF（降级：只取文本流）**。
- EPUB：读 OPF spine 顺序 → 逐 XHTML 取块级元素 → 归一化为 Block。推荐 `foliate-js`（纯 JS、无 DRM 依赖）或 Rust `epub` crate。
- MOBI/AZW3：调用 `kindlegen` 的反向工具链 `kindleunpack` / `mobi` 库解包为 EPUB 再走上面流程；**M0 阶段可先只做 EPUB + TXT**。
- **明确不做**：DRM 移除。只处理用户自有的无 DRM 文件；检测到 DRM 直接报错并提示"请使用已授权的无 DRM 版本"。
- 目录、章节标题、脚注、图片（本地缓存到 `media/`）。
- 断点记忆：按 `bookId + chapterId + blockIndex` 存进度，跨皮肤共享（换皮肤不丢进度）。

### FR-2 内容正规化（最容易翻车的一环）

电子书原始 HTML 带一堆 calibre 生成的内联样式、`<font>`、绝对定位、页眉页脚——直接塞进网页会立刻露馅（字体忽大忽小、居中诗行、章节分隔符）。

- 剥离全部内联样式与 class，只保留语义标签；
- 丢弃 `page-break`、`margin-top: 30%`、`text-indent` 这类排版痕迹；
- 章节标题降级为正文 `h2`（真正的 `h1` 归皮肤所有）；
- 连续空段落合并；对话引号统一；
- **长度自适应**：单章 > 6000 字时按"分页 1/N"切成多页（伪装成社区的长文分页），避免一页滚到底显得诡异。

### FR-3 皮肤系统（首发 8 套）

| 皮肤 | 章节→页面映射 | 优势 | 风险点 |
|---|---|---|---|
| **CSDN 博客** | 1 章 = 1 篇文章；长章分页 | 国内技术岗最常见，长文天然合理，广告/推荐位多，噪声充足 | 大家太熟，细节错一眼能看出 |
| **掘金** | 1 章 = 1 篇文章 | 排版现代、留白多，**阅读舒适度最高** | 噪声少于 CSDN，"太干净" |
| **博客园** | 1 章 = 1 篇随笔 | "posted @ 时间 作者 阅读(2184) 评论(7) 推荐(12)"这一行自带可信度；侧栏分类/档案/排行榜噪声极足 | UI 偏旧，可能显得"在看老古董" |
| **知乎专栏** | 1 章 = 1 篇专栏文章 | 单栏窄版、技术腔最少，**小说/人文类的最佳容器** | 赞同数要长期维护才自然；页面偏窄 |
| **微信公众号** | 1 章 = 1 篇图文消息 | "在电脑上看篇文章"是**最不需要解释**的行为 | 677px 窄栏，信息密度低；代码块排版差 |
| **GitHub Issue** | 1 章 = 1 个 Issue，段落切成评论流 | 天生适合"分段长文本"，评论区就是分段器 | 无广告；正文语气要像讨论；英文语境 |
| **Stack Overflow** | 1 章 = 1 个 Question + 1 个 Accepted Answer | 问题=标题、答案=正文，映射极自然；英文书最佳 | 中文书会显得别扭 |
| **Confluence Wiki** | 1 章 = 1 个 wiki 页面 | 公司内部长时间看 wiki 完全正常，**最安全** | 页面太规整，噪声要额外造；容易被误认为真文档 |

> **选型原则：内容与容器必须匹配。** 同一段小说塞进 CSDN 从头违和到尾，塞进知乎专栏却毫无破绽。真实感的天花板不在模板精细度，而在这里。默认建议：中文技术书→掘金，小说人文→知乎，手册复盘→Confluence，英文技术书→SO，碎片时间→公众号。

> 皮肤不是"换皮"，是**换叙事容器**。同一个"老板走近"的瞬间，CSDN 的掩护是"在读别人的博客"，GitHub 的掩护是"在看一个 issue 的讨论"，Confluence 的掩护是"在查内部文档"。

### FR-3b 主题包 · 行业语境（v0.2 新增）

皮肤只还原**版式**，但被扫进眼里的是**文字**。导航写着「前端 / 后端 / 人工智能」、侧栏推荐「K8s 排查」、广告是「云服务器首年 89」，而正文是《内科学》——**版式对了、语境错了，比版式错更容易被识破**。

主题包是独立于皮肤的行业语料包，两者可交叉组合。它一次性替换：站点原型、导航与版块结构、术语口径、推荐池、广告池、评论语气，以及一张**禁忌词黑名单**。

| 主题包 | 站点原型 | 版式 | 术语口径（示例） | 禁忌词（出现即露馅） |
|---|---|---|---|---|
| 教育 | 教师研修社区 | forum | 文本细读 / 学习任务群 / 分层作业 | commit、部署、QPS |
| 密码学 | 看雪论坛 | blog | Z_A、ENTL、SM2/SM3、PKCS#11 | 心电图、主诉、课文 |
| 信息安全 | 先知社区 | blog | 利用链、打点、ATT&CK | 心电图、定理、抗体 |
| 计算机科学 | 掘金 | blog | ReadIndex、水位、副本、P99 | 主诉、课文、备课 |
| 医疗 | 丁香园论坛 | forum | 主诉、辅助检查、鉴别诊断 | commit、部署、接口 |
| 生物 | 小木虫 | acad | 批次效应、差异表达、FDR | 心电图、commit、Raft |
| 数学 | 数学中国 | acad | 紧算子、谱、一致有界、反例 | commit、抗体、主诉 |
| 物理 | 物理所论坛 | acad | 退相干、T2*、1/f 噪声 | 主诉、课文、commit |

三种版式对应三种可信点：**forum** 靠楼层号、引用块、"本帖最后由…编辑"撑起"我在追一个讨论"；**blog** 靠面包屑、作者行、推荐位撑起"我在读一篇长文"；**acad** 靠摘要卡、关键词、参考文献撑起"我在看学术帖"。

> 详细的数据模型、术语一致性校验（`banned` 命中即重抽）、L1/L2/L3 可信度分级，见 `docs/TOPIC-PACKS.md`；可交互原型见 `prototypes/topic-lab.html`。

### FR-4 噪声引擎（真实感的核心，不是装饰）

真实站点的"脏"是结构性的，必须**分层生成**，不能一坨随机：

1. **广告层**：素材池按站点风格分池（CSDN 池 = 云服务器/训练营/专栏 VIP；SO 池 = Teams/招聘；GitHub 池 = ProTip/Sponsors——GitHub 本来就没广告，硬塞反而假）。
2. **社交层**：阅读量、点赞数**缓慢自增**（30–90 秒 +1）；"最近有 3 人正在阅读"；评论时间用相对时间并随停留时长漂移。
3. **推荐层**：侧栏"热门文章"用**站内真实存在的话题模板**（"K8s Pod 一直 CrashLoopBackOff 排查记录"），而不是书籍内容——这是最容易被忽略的穿帮点。
4. **评论层**：从种子池抽 3–8 条，语气分三类（捧场 / 提问 / 挑刺），**必须与正文弱相关**（正文讲到"缓存一致性"，评论说"楼主这个图看不清，能重发吗"就非常真）。可选接本地 LLM 生成强相关评论。
5. **时间层**：文章"最后更新于 2 小时前"；评论"3 小时前"；页面底部"©2026"。

### FR-5 隐身与应急处置（P0）

| 能力 | 行为 | 备注 |
|---|---|---|
| **Boss Key** | `Esc`（可配 `Ctrl+\``）→ 立即切到预置"工作页"（本地 PDF / 在线文档 / IDE 欢迎页） | 切换必须是**整窗替换**，不能是叠层；切走后本应用不可见 |
| 窗口标题 | 始终 = 伪装站点标题（`xxx的博客-CSDN博客`） | 任务栏、Alt+Tab 缩略图、窗口切换器一致 |
| 进程/应用名 | 可配置（`Code`、`chrome`、`Typora`） | macOS 需注意 Dock 名称 |
| 系统通知抑制 | 阅读期间屏蔽一切 toast / 声音 | 微信弹窗是最大穿帮源，但系统级屏蔽需权限，M3 做 |
| 暂停即静默 | 窗口失焦 > 5 s → 停止数字自增、停止动画 | 防止"没人在看，阅读量还在涨" |
| 剪贴板伪装 | 复制正文 → 复制成"文章引用格式"（标题 + 链接 + 摘要） | 细节，但被抓到一次就完了 |
| 屏共享模式 | 检测到屏幕共享 → 强制切到工作页 | 有争议，M4 可选项 |

**明确不做**：不做摄像头/人脸检测、不伪装成他人身份、不绕过企业 DLP/审计软件。工具只处理"视觉层"，不碰合规层。

### FR-6 阅读体验（不能为了伪装牺牲到没法读）

- 字号 14–20px 可调、行高 1.6–2.0、段间距、正文最大宽度（对齐皮肤的排版规范）；
- 双栏/单栏、护眼背景（**必须是"该站点也有的"夜间模式**，不能自定义米黄色纸感背景）；
- 章节目录（伪装成侧栏 TOC / Issue 侧栏 Labels）；
- 进度：顶部 2px 进度条（伪装成"文章阅读进度"）、`Ctrl+→` 下一章；
- 书签、搜索（在伪装成"站内搜索"的搜索框里搜书籍内容——很妙，搜索结果页还能再伪装一层）。

### FR-7 快捷键

| 键 | 行为 |
|---|---|
| `Space` / `PgDn` | 下一页（伪装成正常滚动） |
| `Ctrl+→ / ←` | 下一章 / 上一章 |
| `Esc` | Boss Key（切工作页） |
| `Ctrl+Shift+Esc` | 紧急隐藏 + 静音 + 记录退出位置 |
| `Tab` | 切换皮肤（需二次确认，防止误触） |
| `Ctrl+= / -` | 字号 |

> 快捷键设计原则：**绝不能占用会触发浏览器/系统原生行为的组合**（`Ctrl+W`、`Alt+F4`、`F5`、`Ctrl+T`），否则用户会在"想翻页"时关掉窗口。

## 5. 非功能需求

- **启动**：冷启动到可读 < 1.5 s；切章 < 100 ms（本地渲染，无网络）。
- **完全离线**：零外网请求。所有图片、字体、图标、广告素材内联或本地。**这条同时是性能要求和隐身要求**——真实站点必然有请求，但请求出现在开发者工具/代理日志里就是破绽，所以用本地 `127.0.0.1` 伪装路径。
- **隐私**：书籍内容、阅读记录、进度只存本地 SQLite；无遥测、无崩溃上报。
- **便携**：单目录可拷贝运行，`books/` + `data.db` + `skins/` 三件套。
- **体积**：< 40 MB（Tauri 目标）。

## 6. 技术方案

### 6.1 两条路线

| 方案 | 形态 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| **A. 本地 HTTP 服务 + 浏览器打开** | Go/Python/Rust 起 `127.0.0.1:port`，浏览器访问 `/article/details/139482716` | 最快出 MVP（1 周）；URL 最真；零安装成本 | 浏览器 UI（标签栏、书签栏）露馅；快捷键被浏览器吃；无法控窗口标题 | **原型 / 自用** |
| **B. Tauri 2 桌面壳** | Rust 内核 + WebView 渲染，`tauri://` 或内部 `127.0.0.1` | 可全权控制窗口标题、图标、快捷键、失焦行为；体积小；可做 Boss Key 整窗替换 | 开发成本高；macOS/Windows 行为需分别适配 | **正式产品（推荐）** |
| C. Electron | 同上但 Chromium 全量 | 生态最熟、调试方便 | 100 MB+、内存高、启动慢 | 快速验证交互 |

**推荐路径**：M0/M1 用 **方案 A** 快速验证"真实性"，同时把皮肤层做成**纯前端、零框架**（无 React），保证 B 阶段可以直接搬进 Tauri WebView。

### 6.2 渲染管线

```
① 解析   epub/mobi/txt ──> Book{ chapters[] }         (Rust: epub crate / JS: foliate-js)
② 净化   raw html ──> Block[]                          (去样式、去排版痕迹、长度切分)
③ 选皮   skin 模板 + CSS ──> DOM skeleton
④ 映射   Block[] ──(skin 的 block 映射表)──> 皮肤特有 DOM
⑤ 注噪   AdEngine / CommentEngine / StatEngine 填槽位   (seed 固定，可复现)
⑥ 上屏   本地 HTTP 路由 or WebView，设置 title/favicon/窗口图标
```

第 5 步是产品差异化的全部。第 4 步是工程量的全部。

### 6.3 Block → 皮肤的映射表（示例：GitHub Issue）

| Block | CSDN | 掘金 | GitHub Issue | Stack Overflow |
|---|---|---|---|---|
| paragraph | `<p>` | `<p>` | 评论正文段落 | 答案正文段落 |
| heading(h2) | `<h2>` + TOC 项 | `<h2>` | 评论内的 `###` | 答案内的 `###` |
| quote | `<blockquote>` 灰底 | 左侧蓝线 | Markdown 引用 | Markdown 引用 |
| code | 深色代码块 + 语言 + 复制 | 深色 + 复制 | ``` 围栏 + 行号 | 代码块 + 复制 |
| list | 圆点列表 | 圆点列表 | Markdown 列表 | Markdown 列表 |
| image | 居中 + "图 x" 说明 | 居中 + 圆角 | 附件式图片 | 内嵌图 |
| 分段 | 一页到底 / 分页 | 一页到底 | **切成评论链** | 单个长答案 |

### 6.4 目录结构

```
touch-fish/

## 7. 里程碑

| 阶段 | 范围 | 产出 | 判定 |
|---|---|---|---|
| **M0** | 4 套高保真静态皮肤 + 假数据 | 本仓库 `prototypes/` | 3 秒盲测通过率 ≥ 2/3 |
| **M1** | EPUB/TXT 解析 + 正规化 + CSDN 皮肤真注入 + 本地 HTTP | 能读完整本书 | 连续读 30 min 不出戏 |
| **M2** | 4 皮肤全部接入 + 噪声引擎（seed 可复现）+ 进度记忆 | 可日常使用 | 换皮肤不丢进度 |
| **M3** | Tauri 壳：窗口标题/图标/Boss Key/失焦静默/快捷键 | 可装机 | Esc 到切走 < 300 ms |
| **M4** | 评论/推荐 LLM 弱相关生成、屏共享检测、MOBI/PDF | 打磨 | — |

## 8. 风险与合规

| 风险 | 说明 | 对策 |
|---|---|---|
| **商标/著作权** | 直接复刻 CSDN/GitHub 的 logo、图标、CSS 属于侵权风险；正式分发尤其危险 | 原型阶段用**自绘近似图形 + 文字 logo**；正式版改为"致敬风格"（相似版式、不同标识），或只做个人自用不分发 |
| 被抓包 | 老板不只看一眼 | Boss Key 是唯一可靠解；不要指望皮肤 |
| 内容不适配 | 小说塞进技术博客，语气突兀 | 提供"贴合度"分级：L0 直出 / L1 轻包装（加技术小标题、术语高亮）/ L2 LLM 改写口吻（M4，默认关） |
| DRM | 商业电子书多为 DRM | 不实现移除；只支持无 DRM 文件 |
| 公司制度 | 部分公司有屏幕审计 | 工具不绕过任何审计；风险由使用者自担 |

## 9. 待确认（需要你拍板）

1. **技术栈**：先走"本地 HTTP + 浏览器"（1 周出可用版）还是直接上 Tauri（3 周但体验完整）？
2. **首发皮肤优先级**：CSDN / 掘金 / GitHub / SO 四套够吗？要不要加 **博客园、知乎专栏、内部 Wiki（Confluence）**？——Confluence 其实是最安全的伪装，但"太干净"，需要额外造噪声。
3. **书籍类型**：主要读什么？如果主要是**中文小说**，CSDN/掘金 的"技术腔"会打架，可能需要 L1/L2 包装；如果是**英文技术书**，Stack Overflow 是最优选。
4. **是否接本地 LLM**（Ollama）做评论/推荐生成？会让真实感上一个台阶，但增加 2 周工作量。
5. **是否需要"多窗口"**：一个窗口伪装、一个窗口真干活。

## 深色模式"阅读页整页还是浅色"的真正原因与修复

用户反馈"阅读页面的深色模式问题还没解决"，现象是设置里选了深色，阅读页仍整页白底，桌面窗口和浏览器都有。

**排查手法（值得复用）**
- `TOUCHFISH_DEV=1 TF_PORT=xxxx ./target/release/touchfish.exe --server`，DEV 模式下 `asset_text` 直接读源码 `assets/`，改 CSS/模板不用重编译。
- 无头 Chrome 截图逐个站点看（`--headless=new --screenshot --window-size=1280,1200`），13 个站点深色都正常。
- 用 CDP（`--remote-debugging-port` + node 内置 WebSocket，不需要 puppeteer）跑 `Runtime.evaluate` 扫描页面里亮度 > 0.55 的大块元素，定位漏改的写死颜色。
- `curl -s localhost:7317/r/<id>/0` 对比 `<html>` 标签：**发现旧进程返回的页面连 `data-theme` 属性都没有**。

**真正的两个原因**
1. **旧进程 + 旧内嵌资源**。assets 是编译期 `include_dir!` 打包的；机器上有一个 09:59 启动的 debug 进程一直活着，那时的资源还没有 dark.css 与主题脚本，它的页面（桌面窗口和 7317 端口）永远整页浅色。改完 assets 必须重新编译并重启，否则看的是旧样式。
2. **阅读页主题脚本 localStorage 优先于服务端**（真 bug）。`layout-blog/forum/acad.html` 里 `mode = stored() || data-theme-mode`，一次按 D 留下的旧值会永久压过设置；而书库是服务端优先，于是出现"书库深色、阅读页浅色"。已用 CDP 精确复现：服务端 dark + localStorage light → `data-theme=light`。

**修复（三套 layout 同一段脚本）**
- `mode = valid(server) ? server : (cached() || "light")`，服务端权威。
- 加载后把 `tf-theme` 对齐成服务端值，旧值不再翻上来。
- `pageshow` 只在 `e.persisted`（真 BFCache）时读缓存，正常加载不覆盖。
- storage 事件照旧保留，跨标签同步。

**新增回归**：`scripts/test_reader_theme.js`，从三套 layout 抽主题脚本套最小 DOM 桩，9 个场景 × 3 版式（服务端/缓存冲突、auto 跟随系统、无服务端时兜底、垃圾值、缓存对齐、pageshow、storage）。`node scripts/test_reader_theme.js` 全绿。

**回归**：13 站点 × 8 主题包 = 104 页，全部 `data-theme="dark"`、无 `%%` 占位符残留。
**产物**：`cargo build --release` + `scripts/package.sh --no-build`，dist 包已更新（SHA256 714f3b0b…）。
**README**：已知问题里补了"改 assets 必须重编译/重启"和"主题以服务端为准"两条。

**教训**：这类"改了没生效"先看进程启动时间和端口归属（`Get-Process touchfish | Select StartTime, Path` + `netstat -ano`），比盯着 CSS 猜快得多。

## v0.8：托盘常驻 + 两种前端二选一

用户确认的产品语义：**X 收起到托盘**（后端常驻），托盘右键是**两个并列按钮**（打开主页面 / 打开网页页面），不记选择。

**改动**
- `UserEvent` 新增 `OpenWindow` / `OpenWeb`；`OpenWeb` = `hide_window` + `crate::open_browser`，保证两种前端同一时刻只露一个（浏览器标签关不掉，只能收起窗口这一侧）。
- 托盘菜单从「显示/收起 + 退出」改成「打开主页面 / 打开网页页面 / separator / 退出」。左键仍是 Toggle，菜单不再重复这个动作。
- **`CloseRequested` 从"退出"改成"收起"**，但保留 `can_restore`（托盘或热键至少一个可用）作为条件：两者都不可用时仍然真退出，否则窗口一收就再也叫不回来。
- `open_browser` 在 main.rs 里改成 `pub(crate)`，桌面壳直接复用，不重抄 CREATE_NO_WINDOW 的 cmd 调用。
- MenuEvent 的 `_` 分支从 `Toggle` 改成 `return`：以后加菜单项不会点一下就莫名收起窗口。
- README 同步：窗口行为、托盘菜单、设计选择第 5 条、功能表。

**验证手法（可复用）**
- 模拟点 X：`$p.CloseMainWindow()` 就是发 WM_CLOSE，不用 Add-Type。之后 `$p.Refresh()` 看 `HasExited`，再打一次 `/api/settings` 确认 7317 还在。
- **本机安全策略禁止 `Add-Type`（运行期编译 .NET）**，所以别用 P/Invoke 的 IsWindowVisible；`Process.MainWindowHandle` 在窗口隐藏后会跳到另一个内部窗口句柄，不能直接当作"仍可见"的证据。
- 托盘菜单点击无法脚本化，这一侧只能靠代码审查 + 手工点一下。

**产物**：release 重编 + 重新打包 dist。

## v0.9：网页按钮与托盘一致 + 热键即时生效

用户的第二个诉求：设置里的「在浏览器中打开」要和托盘「打开网页页面」一致；设置里要有可用的全局热键。

**跨层钩子（关键设计）**
- `main.rs` 加 `UiHooks { hide_window, set_hotkey }` + `static UI_HOOKS: OnceLock<UiHooks>`。桌面壳在事件循环启动后注册两个闭包（各自持一个 `EventLoopProxy`），web 层只调这两下，不 import tao/wry；`--server` 模式永不注册，调用方按"没有窗口"跳过。
- `UserEvent` 新增 `Hide`（只收窗口，浏览器由 web 层开）与 `Hotkey(String)`（换热键）。
- `/api/open-browser`：先 `hooks.hide_window()` 再 `open_browser`。和托盘同一条路径。
- `/api/settings`：保存前记下旧 hotkey，变了就 `hooks.set_hotkey(new)`。

**热键运行时重注册**
- `build_hotkey` 拆成 `install_hotkey_handler`（全局 handler 只装一次）+ `build_hotkey`（返回 manager + HotKey，选项里带 id）。
- `apply_hotkey`：先 unregister 旧的，register 新的；失败就把旧的装回去。宁可维持原状，不能让用户点一下保存就失去唯一的唤出入口。
- **坑 1**：`hotkey_state = apply_hotkey(hotkey_state, &spec)` 在 `FnMut` 闭包里编译不过（can't move out of captured variable），要先 `take()` 再放回。
- **坑 2**：`HotKey::new` 每次自增 id，`old == next` 永远不等，只能比 `mods` + `key`。
- `can_restore` 从启动常量改成每帧算（`tray.is_some() || hotkey_state.is_some()`），重注册失败回退后仍准确。

**设置页**
- 热键从面板中部移到「在浏览器中打开」下面，改名「全局热键」，文案写清"呼出 / 前台时按则收起 / 立即生效 / 被占用会保留原键"；加「默认」按钮与 `hotkeyLooksOk` 形状校验（至少一个修饰键 + 主键）。
- 网页模式隐藏 `#rowHotkey` / `#rowTray`（没有窗口可唤）。
- 「在浏览器中打开」的 toast 改成"已收起到托盘，并在浏览器中打开"。

**验证**
- debug 启动后连改两次热键，stderr 依次打出 `[hotkey] 已换成 Ctrl+Alt+G`、`已换成 Ctrl+Alt+F`。
- POST `/api/open-browser`：主窗口标题从 `白夜行…- CSDN` 变为空（窗口已隐藏），进程存活。副作用是测试时真的弹了一个浏览器标签，需要手动关。
- `cargo test` 13 项通过；release + dist 重打包。

**HTML 里没有热键项？** 有的，`#setHotkey` 一直在设置面板中部，只是位置靠下、文案叫「唤出热键」+「改完需要重启」，容易被当成摆设。这轮才真正做成即时生效。

## v0.10：正文文章化 + 文中广告

用户的原话：「所有的内容都是通过正文，应该增加一些引用、小字等结构化处理，否则大段落正文一眼能看出问题」，随后追加「正文中适当插入广告模块」。

**先量化问题**：《白夜行》33 章、7687 个 P、119 个 H、1 个引用、5 段代码、9 个列表——就是「标题 + 几千个短段」，平均值 39.5 字/段。

**渲染层新增 `shape_blocks`（render.rs）**，只在原文结构稀疏时启用（`ps<10`、`hs*8>=ps`、`rich*12>=ps` 任一命中就原样返回）：
1. 合并碎段：相邻 ≤70 字的纯文本段拼到 ~150 字，一行一句的对话感立刻消失（不动文字）。
2. 原文「1」「2」「一」这类纯编号标题改写成「01 背景」——`<h2>1</h2>` 比没有标题更像小说。
3. 按密度补小标题：每走 8 段、后面还剩 5 段以上就补一个，标题从 16 个模板词里按 seed 轮转。
4. 每 4 节挑一段 60–220 字的叙述改成引用块（原文照搬），密度靠 `sec_no % 4 == base % 4` 控制。
5. 「注：」「资料来源」开头的短段降为 `Block::Small`。
6. 分页后 h2 编号会重新按页编号（`renumber_heading`），否则第二页会出现「09 过程」。

**模型/解析层补齐**（原来这些标签全被压成普通段落）：
- `Block::Q` 加 `cite`、`Img` 加 `cap`、`Table` 加 `cap`、新增 `Small`，都带 `#[serde(default)]`，旧 book.json 仍能读。
- html.rs 解析 `<blockquote><cite>`（只在 blockquote 内当出处）、`<figcaption>` / `<caption>`（结束时间回填到最近的图/表）、顶层 `<small>`。
- 新增行内缓冲 `cite_buf` / `cap_buf`，on_text 里优先走它们，避免出处混进正文。

**文中广告**
- `mid_ads_html` 从 `pack.ads[1..]` 取，跳过顶部大卡用的第一条；每个主题包补到 4 条（8 包 × 2 条新文案）。
- `body_html` 按段落数插：≥5 段插 1 条（页面中部），≥18 段插 2 条（2/5、4/5 处）。
- `.ad-mid` 全部走 CSS 变量，深色不用另写覆盖。

**分页也顺手修了**：原来按 9 块一页，一章能被切成 17 页。改成「每页约 3000 字 + 站点块数上限」双约束（`CHARS_PER_PAGE`），sites.json 的 paging 调到 80/90。现在一章十万字以内基本 3–10 页。

**验证**：208 次渲染（13 站点 × 8 包 × 2 页）全 200、无占位符；CSDN / 知乎 / GitHub / 小木虫 / 公众号逐个截图确认小标题、引用、广告、导语在浅色和深色下都成立。
**教训**：改 assets 后开发用 `TOUCHFISH_DEV=1`，但**改 Rust 必须重编译并重启进程**；`Stop-Process` 一定要用 PowerShell 工具，写在 Bash 里那行会被当成命令名直接失败，结果新进程因端口占用退出，curl 打到的还是旧进程。

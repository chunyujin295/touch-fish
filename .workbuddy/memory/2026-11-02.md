# 2026-11-02

## TouchFish（摸鱼阅读器）— 需求文档 + 4 套皮肤原型

**目标**：把 EPUB/MOBI 电子书渲染成 CSDN / 掘金 / GitHub Issue / Stack Overflow 的网页外观，让长时间阅读在工位上看起来像在查技术资料。

**产出**
- `docs/PRD.md`：定位、为什么选"技术社区网页壳"、信息模型（Book→Chapter→Block→Slot）、FR-1..FR-7、非功能需求、两条技术路线对比（本地 HTTP vs Tauri 2）、6 步渲染管线、里程碑 M0–M4、商标/合规风险。
- `prototypes/index.html`：总览页（4 皮肤对比 + 槽位契约表 + 真实感清单）。
- `prototypes/skins/{csdn-article,juejin-article,github-issue,stackoverflow-question}.html`：零依赖纯静态高保真页面。

**关键设计决策**
1. Block 是唯一跨皮肤中立单位；皮肤 = HTML + CSS + block 映射表，新增皮肤不碰解析器。
2. 槽位用 `data-tf-slot` 标记（article-title / body / toc / comments / stat-* / ad-*），便于引擎 querySelector 注入。
3. 章节→页面映射按皮肤不同：CSDN/掘金=文章（长章分页）、GitHub=Issue+评论链（评论区当分段器）、SO=Question+Accepted Answer。
4. 噪声分层：广告池按站点分池（GitHub 本来无广告，用 ProTip/bot 评论替代）、推荐位必须与书籍无关、评论语气分捧场/提问/挑刺。
5. 噪声 seed 必须可复现，否则刷新后广告评论变化反而露馅。
6. Boss Key（Esc→整窗替换工作页）优先级高于真实感；失焦即停数字自增。
7. 明确不做：DRM 移除、摄像头检测、绕过企业审计。

**验证**：用 Chrome headless 截图逐页检查版面，修掉 3 处问题（CSDN meta 行换行、悬浮栏负偏移被裁、GitHub 顶栏 + 按钮挤压、SO 行内 code 断行）。

**待用户拍板**：技术栈（本地 HTTP 先上 vs Tauri 直上）、是否加博客园/知乎/Confluence 皮肤、书籍类型（中文小说 vs 英文技术书）、是否接本地 LLM 生成评论。

**踩到的坑（供复用）**
- 微信代码块用 `<div>` 直接放多行文本 → 换行被折叠，必须加 `white-space:pre`。
- 假二维码别用 `repeating-linear-gradient` 拼，会糊成网格；改用 JS 按 25×25 生成格子 + 三个 finder 方块，seed 固定，视觉上以假乱真。
- Confluence 顶栏 brand 是 `<a>`，会被全局 `a{color:var(--link)}` 覆盖成深蓝看不清，要显式 `color:#fff`。
- 孤儿 `<li>` 不在 `ul` 内也会渲染项目符号，侧栏必须 `list-style:none`。
- Chrome headless `--dump-dom` 在本机返回空，不能用它做断言；改用截图 + 独立小页面验证脚本。

**新增设计判断**：真实感天花板 = 内容与容器是否匹配，不是模板精细度。8 套皮肤的价值在于按书籍类型切换，而不是全部做得更精细。

## 追加：行业主题包层（v0.2）

**核心判断**：真实感要三层匹配 —— 内容（书）× 容器（皮肤）× 语境（主题包）。皮肤只解决"版式像不像"，老板扫进眼里的是"文字像不像"：导航写「前端/后端/AI」、推荐位全 K8s、广告是云服务器，正文却是《内科学》——版式对、语境错，比版式错更容易被识破。

**新增文件**
- `docs/TOPIC-PACKS.md`：8 个主题包规格、数据模型（含 `banned` 禁忌词）、术语一致性校验、L1/L2/L3 可信度分级、组合矩阵、落地计划 M2-a~c。
- `prototypes/topic-lab.html`：可交互实验台。8 个 chip 切换，整页重渲染（站点名/导航/版块/标题/正文/标签/侧栏/广告/评论/页脚备案号/地址栏 URL/浏览器 title 全换）。

**8 个主题包 × 3 种版式**
教育→forum(教师研修社区)、医疗→forum(丁香园)、密码学→blog(看雪·深色头)、信息安全→blog(先知)、计算机→blog(掘金)、生物→acad(小木虫)、数学→acad(数学中国)、物理→acad(物理所论坛)。

**关键设计**
1. `banned` 字段是整套设计的关键：定义"这个语境里不该出现什么"。医疗帖出现 commit、教育帖出现 QPS，比广告位少一个更容易穿帮。渲染前校验，命中即重抽。
2. 论坛版式被低估：楼层号 + 引用块 + `本帖最后由…编辑` 三件套，天然解释"为什么停在这一页这么久"。
3. 学术版式靠 摘要卡（背景/方法/结果/关键词）+ 参考文献 + 衬线标题 撑可信度。
4. 单一 HTML 内用 `PACKS` 数组 + 三个 render 分支（forum/blog/acad）实现，零依赖，hash 路由（`#med`）可直接定位。

**踩到的坑（供复用）**
- 侧栏条目 `<a class="item">` 里长标题会把右侧标签（已应助/申请/预约）挤出卡片：文本 span 必须 `flex:1;min-width:0`，标签 `flex:0 0 auto`，否则溢出被裁。
- 页面内锚点跳转会被 sticky 顶栏盖住：`h2.sec` 要加 `scroll-margin-top:84px`。
- Chrome headless 截图在 Git Bash 下 `--screenshot="C:/a/b.png"`（正斜杠）会 exit 0 但不产出文件；必须用 `"C://a//b.png"` 双反斜杠转义。
- 同一命令里连续跑多个 Chrome 会互相抢 user-data-dir 而静默失败；每个实例单独 `--user-data-dir` + `sleep 1`。
- `--dump-dom` 在本机返回空，断言只能靠截图（上轮已知，本轮再次确认）。

**解释口径**：用户说的"信息"按《信息安全/网络攻防》实现，与"密码"（密码学与国密）拆成两个包。若指信息论/通信，主题包是纯数据，换 JSON 即可。

## 追加：正式开发（Rust 后端 + 书库界面）

用户拍板技术栈走 Rust，并要求"人性化和现代化的前端页面"。工具链由我直接装（用户选"现在装"）。

**工具链（本机一次性）**
- 官方 `static.rust-lang.org` 只有 ~11KB/s，curl 直接超时；改 `rsproxy.cn` 下载 rustup-init 才有 500KB/s+。
- rustup 首次装卡死 7 分钟、`rustup default` 报 `missing manifest in toolchain`：`taskkill rustup-init` → `rustup toolchain uninstall` → `RUSTUP_DIST_SERVER=https://mirrors.tuna.tsinghua.edu.cn/rustup rustup toolchain install stable-x86_64-pc-windows-msvc --profile minimal`。装成 rustc 1.99.1，复用已有 VS2022 + Win SDK。
- crates 直连 403：`~/.cargo/config.toml` 里 `[source.crates-io] replace-with='rsproxy-sparse'` + `sparse+https://rsproxy.cn/index/`。
- 注意：Git Bash 里 `cargo` 不在默认 PATH，每条编译命令都得 `export PATH="$HOME/.cargo/bin:$PATH"`。

**架构**
- 依赖只有 9 个：axum 0.7 / tokio / serde / serde_json / anyhow / zip(deflate) / quick-xml / sha2 / encoding_rs / chardetng / include_dir。
- `model.rs` 的 `Block` 是唯一中立模型（P/H/Q/Code/List/Img/Table/Hr），解析层只产 Block，渲染层只吃 Block，皮肤与主题包都在模型之外。
- 书库是纯 JSON 文件（`books/{id}.json` + `progress.json` + `settings.json`），不引数据库。
- assets 双通道：`TOUCHFISH_DEV=1` 读磁盘（改 CSS 刷新即见），否则读 `include_dir!` 编译进去的副本，单文件分发。
- 书库界面零依赖手写 JS/CSS，无 node、无构建。

**踩到并修掉的坑（按发现顺序）**
1. EPUB 导入报"没有解析出任何正文"：`<item>` `<itemref>` `<meta>` 是自闭合标签，`quick-xml` 走 `Event::Empty` 而不是 `Start`，原代码只在 Start 里收，导致 manifest/spine 全空。抽出 `on_elem()` 两个分支都调，并给 spine 为空时按 manifest xhtml 兜底。
2. TXT 书名变成哈希 id：用了临时文件 `tmp/{id}.txt` 取 file_stem。改成 `parse(path, id, display_name)` 传原始 filename。
3. `cargo build` 报 `failed to remove touchfish.exe`（os error 5）：服务进程占着文件，先 `taskkill //F //IM touchfish.exe`。
4. **TXT 文件名 `《书名》作者.txt` 直接把请求打崩**（`txtbook.rs:61` panic: `start byte index 1 is not a char boundary; it is inside '《'`）：`stem.find('《')` 返回字节下标 0，原代码写 `a + 1`，而 `《` 占 3 字节。改成 `a + '《'.len_utf8()`。这类"中文当 ASCII 数"的错误在 Rust 里是 panic 不是乱码，会把整条连接 reset（HTTP 000，浏览器白屏）。同时给 import 的解析调用套 `catch_unwind`，坏书降级成 400 而不是断连。
5. `.rp` 类名冲突：顶部阅读进度条 `.rp{position:fixed}` 与论坛楼层右下角"举报·回复" `.rp{margin-left:auto}` 撞了，后者继承 fixed，文字飘到窗口左上角。进度条改名 `.rprog`。
6. GitHub 深色顶栏 logo 被染成金色（那是看雪的配色）：`base.css` 里所有 `.hd.dk` 都套了金色渐变，挪到 `assets/sites/all.css` 的 `body.s-xuekan` 下。
7. 点赞数与收藏数一模一样（213/213）一眼假：`star = (like / rng.range(3,7)).max(1)`。
8. 学术版式摘要卡直接复述正文第一段：改成合成的摘要体（"围绕「章名」展开，先交代问题背景与观测到的现象"）。
9. TXT 开头那段无章节标记的文字单独成章，帖子标题就叫"正文"，一眼假：改为并进第一章；且书名/作者/版权这类元信息行（`《…》`、`作者`、`声明`…）在合并时过滤掉，不混进正文首段。
10. 章节名过长时帖子标题长到不像真人写的：`wrap_title` 里先按字符（不是字节）截到 30 字加省略号，再套主题包的标题包装器。

**环境限制（重要，别再试）**
- Chrome / Edge 的 `--headless=new --screenshot` 在本机已彻底失效：rc=0、无 stdout/stderr、不产出文件，也不产生独立 browser 进程（疑似参数被已运行的 Chrome 接管）。两个浏览器表现一致，`--no-sandbox`、换 user-data-dir、换绝对/相对路径、加 `--virtual-time-budget` 全部无效。
- `--dump-dom` 同样返回空。
- 结论：本机视觉回归只能靠人工看，或者走接口抓 HTML 做结构断言（`curl` + python 正则）。

## 追加：桌面窗口（v0.3）

用户要"图形化界面"。判断：他要的是**双击就能开的桌面窗口**，不是在浏览器里开 localhost。

**技术选型：wry + tao，不用 Tauri**
- Tauri 的价值在 node 前端工程化（打包、插件、IPC 全家桶），而这里界面是手写 HTML + 服务端直出，没有构建步骤，Tauri 的复杂度全用不上。
- 直接拿 wry（Tauri 的底层，就是 WebView2 的 Rust 绑定）+ tao（窗口 / 事件循环），依赖从几百个降到几十个。release 编译 2 分钟，Tauri 至少十几分钟。
- 架构上没重写界面：**窗口只是壳，指向进程内的 axum 服务**。同一套页面浏览器能开、窗口也能开，调试用前者，日常用后者。
- 本机 WebView2 运行时来自 Edge（EdgeWebView/Application/156.0.4314.50），不用额外装。

**实现要点**
- tao 的事件循环必须占主线程 → tokio runtime 挪到后台线程（spawn_server），主线程留给窗口。原来的 #[tokio::main] 拆掉，改成手动 Builder::new_multi_thread。
- 窗口标题跟随页面标题：WebView2 的 with_document_title_changed_handler 回调不在主线程，改成往 EventLoopProxy 发自定义事件，主线程里再 set_title。少这一步窗口标题会一直停在初始值，跟多标签浏览器对不上。
- 窗口位置 / 大小 / 最大化记忆存 window.json；最大化只存标记不存尺寸，否则下次变成铺满的普通窗口。
- **Boss Key 在桌面壳里是关窗，不是跳 about:blank**：with_navigation_handler 拦到 about:blank 就发 Boss 事件 → 存状态 → ControlFlow::Exit。留一个白窗口比什么都可疑。浏览器模式下仍是普通跳转。
- 单实例：启动前先 TCP 探一下端口的 /api/settings 里有没有 version 字段，有就直接连上去，不再起服务，也不报"端口被占用"。
- windows_subsystem="windows" 只在 release 生效（debug 保留控制台），--server 模式照旧有输出。

**踩坑**
- WebViewBuilder::with_web_context 在 wry 0.57 不存在，正确写法是构造器 WebViewBuilder::new_with_web_context(&mut ctx)。
- Icon::from_rgba 要的是**裸 RGBA**，不是 PNG 的逐行 filter 格式；自己写的生成脚本每行要多输出一个 filter byte，喂给 tao 之前必须剥掉，忘了就是花屏。
- 自测 Esc 没法自动化（Add-Type 和 WScript.Shell 的 COM 实例化都被安全策略拦了，SendKeys 用不了）。改成加一个调试开关 TF_BOSS_TEST=1，用 with_initialization_script 注入 location.replace("about:blank") 触发同一条路径——窗口确实在 1.5 秒后自行退出、window.json 正常落盘，说明 navigation handler 对 about:blank 是会触发的。这个开关只在 debug 编译里存在。

**顺带做的**
- 应用图标：Python 直接手写 PNG / RGBA（圆角渐变方块 + 三条书页线），64×64，不引 image 库。
- 站点细节件（真实感的关键，模板写在 sites.json 里，加站点仍不用改 Rust）：CSDN 顶部专栏收录条、博客园文末 posted @ 行、知乎底部赞同条。
- 细节件里的数字要分口径：专栏"已收录 N 篇"不能用评论数，单开了 posts 变量；阅读数用原数不用 2.2w（博客园就是裸数字）。
- git init + 首版提交（44 个文件），加 .gitattributes 统一 LF，免得每个文件都刷 CRLF 警告。
